# GSWorkHUB

Рабочая операционная система одного человека. Задача — **утром сказать, что
делать**.

Склад — обычные markdown-файлы под git, формат
[Open Knowledge Format](https://cloud.google.com/blog/products/data-analytics/how-the-open-knowledge-format-can-improve-data-sharing).
Никакой базы, никакого приложения-владельца: любой инструмент читает эти файлы
напрямую, Obsidian можно открыть на этой папке как просмотрщик.

## Три корня — три сорта данных

```
raw/     события   что произошло — не переписывается никогда
work/    позиции   что держим в работе — правится свободно
wiki/    виды      сводки — пересчитываются, руками не трогать
```

Файл не может лежать в двух корнях. Это главный инвариант.

## Первый запуск

Этот репозиторий публичный, и данных в нём нет — только устройство. Ваш склад
наполнится данными с первого дня, поэтому первым делом он переезжает в свой
закрытый репозиторий:

```bash
git clone https://github.com/murad1986/GSWorkHUB.git gsworkhub && cd gsworkhub && rm -rf .git && git init -b master
```

Дальше — зависимости и проверка:

```bash
python3 -m pip install -r requirements.txt && make gates
```

Оба гейта обязаны быть зелёными на чистой копии: `ЛИНТ: чисто` и
`VERIFY: сошлись все N случаев`. Дальше — [docs/ustanovka.md](docs/ustanovka.md):
что заполнить в первый день, какие ключи завести, что можно не подключать.

## С чего начинается сессия

`make welcome` — состояние склада одним экраном: ветка, незакоммиченное, итог
гейтов, верхние сигналы внимания и когда он собран. Запускается сам при входе в
сессию агента (хук `SessionStart` в `.claude/settings.json`).

`make today` — живой рабочий вход. Он каждый раз читает `raw/` и `work/`:
сначала неразобранное, затем уже начатое и ожидания, после — кандидатов на
свободные места. Не больше семи рабочих строк; просмотр ничего не начинает
автоматически. Ёмкость берётся из данных; при необходимости её можно задать
явно: `make today CAP=full|half|low`.

Явный выбор записывается командой:

```sh
make work ACTION=take ITEM=work/clients/alfa/commitments/sobrat-kartu-processov.md
make work ACTION=finish ITEM=work/clients/alfa/commitments/sobrat-kartu-processov.md \
  RESOLUTION=raw/sources/2026-08-20-karta-processov.md
```

`make attention` — пересчитываемый диагностический вид, а не очередь на день.

Все переходы, обязательные аргументы и реакции без изменения позиции — в
[инструкции по рабочему циклу](docs/work-cycle.md).

## Внешние источники

Ни один из них не обязателен: без ключей склад работает целиком, а конкретный
вход просто молчит.

| Что | Команда | Что нужно |
|---|---|---|
| Разговорный вход и голос | `make telegram ACTION=check` | токен бота, id владельца |
| Расшифровка голоса | внутри telegram-входа | ключ Deepgram |
| События календаря | `make calendar` | доступ Google Calendar |
| Диктофон, переписка, документы | `make capture FILE=…` | агент с MCP — см. [connector-plaud.md](docs/connector-plaud.md) |
| Полный обход, 3 раза в сутки | `make context` | [avtosbor-konteksta.md](docs/avtosbor-konteksta.md) |
| Календарь в фоне на macOS | `make local-sync ACTION=install` | доступ Google Calendar |

`make check-env` показывает, что на этой машине есть, а чего нет. Ключи кладутся
в `config/secrets.env` (образец — `config/secrets.env.example`); файл в git не
попадает.

## Что здесь уже лежит

Посевной набор: вымышленный клиент «Альфа», один процесс, по одной записи
каждого типа — встреча, интервью, наблюдение, источник, обязательство, вопрос,
риск, решение, замысел, цель. Это образцы формы, а не данные: их можно удалить,
когда появятся свои, — но лучше сначала завести свои рядом и сравнить.

Профиль владельца — [work/me/profil.md](work/me/profil.md) — заготовка с
вопросами. Пока он не заполнен, агент не додумывает человека за него.

## Проверки

```bash
make gates      # линт схемы + мета-гейт: проверки ловят то, ради чего написаны
make lint       # склад соответствует схеме
make verify     # проверки не вакуумны
```

Красный линт — это не поломка кода, а расхождение склада со схемой: битая
ссылка, дубль ключа, обязательство без источника.

## Чего здесь нет

Слоя личного развития: карты навыков, доказательств владения, полки литературы
и атласа развития. Он остался в исходной системе — подробности в конце
[схемы склада](docs/storage-schema.md).

Данные о восстановлении (`make capacity`) берутся из отдельного хранилища
показателей; переменной `HEALTH_STORE_ROOT` нет — ёмкость честно отвечает
«неизвестна», и это рабочее состояние, а не поломка.
