# Установка: первый день со складом

Инструкция для того, кто получил копию системы и открывает её впервые.
Порядок важен: сначала склад должен работать сам по себе, и только потом к нему
подключаются внешние источники.

## 0. Перевести склад в свой закрытый репозиторий

Этот репозиторий публичный: в нём только устройство системы, данных нет. Ваш
склад данными наполнится с первого дня — встречи, обязательства, переписка, —
и оставаться в публичном месте он не должен.

```bash
git clone https://github.com/murad1986/GSWorkHUB.git gsworkhub
cd gsworkhub
rm -rf .git && git init -b master && git add -A && git commit -m "склад заведён"
```

Дальше — свой закрытый репозиторий (`gh repo create <имя> --private
--source=. --push` или через веб-интерфейс). Проверить, что публичного origin
не осталось: `git remote -v` должен показывать только ваш адрес.

## 1. Проверить, что всё живо

```bash
python3 -m pip install -r requirements.txt
make gates
```

Ожидаемый ответ — две зелёные строки: `ЛИНТ: чисто` и
`VERIFY: сошлись все 423 случаев`. Первая говорит, что склад соответствует
схеме; вторая — что сами проверки не пустые.

Нужен python 3.11 или новее и git: без git линт не сможет сверить диск с
историей и скажет об этом прямо.

## 2. Завести себя

Три файла, десять минут:

- `work/people/ivan-petrov.md` — переименовать под себя, поправить имя и роль.
- `work/me/me.md` — поле `person` ведёт на карточку выше.
- `work/me/profil.md` — заготовка с пятью вопросами. Заполняется своими
  словами; пустой профиль честнее выдуманного.

После правки:

```bash
make index && make lint
```

## 3. Завести первого клиента

Скопировать папку `work/clients/alfa` под своё имя, поправить `client.md`:
название, префикс ключей (`prefix: ALF` → свой), режим, описание. Записи внутри
переписать под настоящую работу или удалить.

Ключ записи — `<префикс>-<буква типа>-<номер>`: `C` обязательство, `Q` вопрос,
`D` решение, `R` риск, `P` процесс. Ключ уникален по всему складу — линтер это
проверяет.

## 4. Убрать образцы

Посевные записи — «Альфа», Анна Смирнова, встреча 3 августа — учебные. Когда
свои появились, они удаляются одной командой:

```bash
rm -rf work/clients/alfa work/people/anna-smirnova.md work/ideas/shablon-priema-zayavok.md
rm raw/meetings/2026-08-03-* raw/interviews/2026-08-05-* raw/observations/2026-08-05-* raw/sources/2026-08-01-alfa-*
make index && make lint
```

Линт после этого обязан остаться чистым: если он ругается на ссылку в никуда,
значит что-то из своего уже ссылалось на образец.

## 5. Подключить источники — по одному

Ключи живут в `config/secrets.env`. Файл в git не попадает никогда: создаётся из
образца.

```bash
cp config/secrets.env.example config/secrets.env
make check-env
```

`make check-env` печатает, что на этой машине есть, а чего нет. Ничего не
подключено — склад всё равно работает: молчит только соответствующий вход.

**Telegram — разговорный вход.** Бот заводится у `@BotFather`, токен идёт в
`TELEGRAM_BOT_TOKEN`. `TELEGRAM_ALLOWED_USER_ID` — числовой id владельца;
сообщения от всех остальных бот игнорирует. Проверка: `make telegram
ACTION=check`.

**Deepgram — расшифровка голосовых.** Ключ проекта в `DEEPGRAM_API_KEY`. Без
него голосовое сохранится в `raw/inbox/` как файл и будет ждать расшифровки.

**Google Calendar — контекст дня.** Календарь читается, а не управляется:
события приходят в `raw/inbox/` как контекст. Проверка: `make calendar`.

**Plaud, переписка, документы, доски — через агента.** Своего коннектора у них
нет: данные приносит агент своими MCP-серверами и передаёт в общий вход
`make capture`. Как устроено — [connector-plaud.md](./connector-plaud.md).

Календарь в фоне на macOS ставится службой один раз: `make local-sync
ACTION=install`. Полный обход вместе с источниками агента — `make context`,
расписание на три захода в сутки — [avtosbor-konteksta.md](./avtosbor-konteksta.md).

**Развернуть всё сразу и собрать историю.** Готовый промпт агенту —
[prompts/razvorachivanie.md](./prompts/razvorachivanie.md): семь шагов от
проверки гейтов до автосбора, с остановкой после каждого.

## 6. Ежедневный порядок

| Когда | Команда | Что происходит |
|---|---|---|
| Утром | `make today` | что делать сегодня, не больше семи строк |
| В течение дня | `make work ACTION=take ITEM=…` | взял в работу |
| Закрывая | `make work ACTION=finish ITEM=… RESOLUTION=…` | закрыл с результатом |
| Раз в неделю | `make reflect` | работает ли сама система |
| Перед коммитом | `make gates` | склад соответствует схеме |

Переходы целиком — в [work-cycle.md](./work-cycle.md).

## 7. Что делать, когда система мешает

Правило есть — оно живёт в файле, а не в голове: пороги внимания и лимиты
работы задаются в `config/attention.yml` без правок кода. Строка поднимается
слишком рано — меняется число, а не привычка её игнорировать.

Появилось то, чему в складе нет места, — не заводить папку «пока так»: три
исхода описаны в контракте, раздел «Система не ломается исключениями»
([AGENTS.md](../AGENTS.md)).
