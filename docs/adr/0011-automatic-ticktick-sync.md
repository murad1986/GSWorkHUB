# ADR 0011 — Актуальные обязательства автоматически уходят в TickTick

- Статус: **accepted** (решение владельца, 2026-08-12)
- Дата: 2026-08-12
- Задача: TASK-25
- Изменяет: [0010-calendar-ticktick-warehouse-sync.md](0010-calendar-ticktick-warehouse-sync.md), пункт 8
- Развито: [0012-autonomous-ticktick-calendar-sync.md](0012-autonomous-ticktick-calendar-sync.md)

## Контекст

Сверка находила расхождение, но наружу не писала. Семь задач были заведены
8 августа вручную; три обязательства, появившиеся 11 августа, остались только в
складе. Постоянный проход мог каждые пять минут сообщать об одном и том же
разрыве, но не устранял его. На сервере этот проход вдобавок не запускался рядом
с Telegram-входом.

Ручное подтверждение каждой технической копии не является решением человека о
содержании задачи: формулировка, срок, владелец и источник уже подтверждены в
обязательстве склада. Создание их отражения в канале действия — обратимая
доставка принятого, а не новое обязательство.

## Решение

1. Каждый проход `make sources` автоматически создаёт в выбранном списке
   TickTick живые обязательства уровня `now` и обязательства с датой в ближайшие
   семь дней.
2. Обязательства `next` и `later` без близкого срока остаются только в складе.
3. Перед созданием проверяются два признака: поле `ticktick` в карточке и метка
   `Из склада: <путь>` в теле существующей задачи. Если API успел создать
   задачу, а запись связи сорвалась, следующий проход восстанавливает связь и не
   создаёт копию.
4. Галочка, перенос и исчезновение по-прежнему приходят как внешние события.
   Галочка не закрывает обязательство без ссылки на результат.
5. Google Calendar остаётся только читаемым контекстом. Автоматическая внешняя
   запись разрешена этим решением только для TickTick.
6. Серверный дежурный одновременно запускает Telegram-вход и постоянную сверку.
   Остановка любого обязательного процесса видна и завершает контейнер целиком.
7. На сервере ключ передаётся через `TICKTICK_ACCESS_TOKEN`; в репозиторий он не
   записывается.

## Последствия

- Новое актуальное обязательство появляется в телефоне не позднее следующего
  прохода, по умолчанию через пять минут.
- Повторный проход безопасен и не создаёт вторую задачу.
- Недоступность TickTick называется в строке сверки и не мешает принять
  календарь; следующий проход повторяет попытку.
- Истечение нынешнего ключа остаётся эксплуатационным ограничением: без
  `refresh_token` после 13 октября 2026 нужна повторная авторизация.
