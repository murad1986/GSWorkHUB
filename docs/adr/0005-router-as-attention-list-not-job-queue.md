# ADR 0005 — Router как список внимания вместо Agent Job Queue

- Статус: **accepted** (решение владельца, 2026-07-25)
- Уточнено: [ADR 0006](0006-live-work-cycle-and-honest-feedback.md) вернула
  `in-progress` в само обязательство, не возвращая Agent Job Queue
- Дата: 2026-07-25
- Контекст-док: [../why-it-broke.md](../why-it-broke.md)
- Задача: TASK-003.03

## Контекст

Аудит 25 июля 2026 нашёл четыре механики операционного слоя с **нулём вызовов из
production**: Agent Job Queue, Corrections Log, `morning_brief`,
`session_start_context`. Ноты в vault при этом обещают работу, которой нет
(«Cron ставит jobs», «SessionStart подмешивает последние N»).

Эта ADR закрывает первую из четырёх — Agent Job Queue. По остальным трём
решение не принято.

**Что Job Queue должна была делать.** Отвечать на вопрос, на который не отвечает
ни один другой механизм: *что было начато и чем кончилось.* Router, health и
`pending` описывают состояние vault; очередь описывала бы работу над ним —
взято, отложено, упёрлись в человека. Знание «агент за что-то брался» сейчас
исчезает вместе с закрытием сессии.

**Почему она не работает.**

- Ни входа, ни выхода: cron задачи не ставит, скиллов-исполнителей нет, CLI нет.
- Два типа из четырёх подпирают несуществующие механики: закрытия недели в
  системе нет (индекс `weekly-review` пуст во всех четырёх проектах), детектора
  брошенных сессий нет.
- Два других дублируют работающее: `meeting-classify` ≈ `pending`,
  `review-confirm` ≈ команда `review-list`.
- Дедупликация не срабатывает никогда: в ключ входит время до секунды, поэтому
  повторный запуск cron создаёт вторую копию. Тест этого не ловит — подаёт
  одинаковое время в оба вызова.
- Таблица не рендерится: строки пишутся через `append` с маркером-комментарием —
  та же болезнь, что чинилась в Review Queue (коммит 62fdbb3).

**Что за неё говорит.** Состояния «взято в работу» и «упёрся в человека» не
выводятся из содержимого vault. Это знание существует, только если его записать.

## Решение

**Не строить очередь. Превратить Router из набора счётчиков в список внимания.**

Вместо `Pending дней: 0 / Review Queue: 0` — конкретные строки, пересчитываемые
при каждом обновлении из живого состояния:

```
## Требует внимания
- [meeting-capture] 2026-07-25 собран, не разобран — 4 элемента
- [review-confirm] 5 элементов ждут подтверждения (2 решения)
- [session-orphan] Альфа: сессия открыта 3 часа
- [overdue] ALF-MI-6A1EE3C0 просрочен на 2 дня
```

Ключевое свойство: **строки вычисляются, а не хранятся.** Строка появляется,
потому что снимок не разобран, и исчезает, когда разобран. Нечего
дедуплицировать, нечего чистить, нечему разойтись с реальностью.

То, что из состояния не выводится, хранится отдельно и минимально: короткий
список «отложено / жду ответа» с причиной и датой. Обычно пустой. Это
`blocked-human` без статусной машины вокруг.

## Обоснование

Корневой причиной половины находок аудита было расхождение хранимых копий одного
знания: три словаря статусов Open Items, два реестра контейнеров, два словаря
префиксов, счётчики Router против живого состояния. Очередь — ещё одна хранимая
копия того, что в основном выводится. Производное состояние не может разойтись с
источником по построению.

Цена тоже несимметрична. Очередь: починить дедупликацию и рендер, CLI, вызовы из
cron и `apply_packet`, детектор сессий, механизм закрытия недели, политика
очистки `done` — семь новых движущихся частей. Список внимания: детектор
брошенных сессий поверх уже работающей проверки активной сессии, плюс проброс
overdue, который `vault_health` уже считает, — в Router для него есть пустой слот
«Blockers / overdue», куда цифру просто не передают.

## Последствия

- Agent Job Queue (`enqueue_job` / `list_jobs` / `update_job`) и нота
  `14 Agent Ops/Agent Job Queue.md` выводятся из контура. Код убирается из
  репозитория (возвращается через git), нота переносится в архив с причиной —
  не удаляется, по правилу проекта.
- Router получает раздел «Требует внимания» и перестаёт быть набором счётчиков.
- Появляются два детектора, которых не было: брошенная сессия и проброс overdue.
- Теряется: приоритеты задач и явное `in_progress`. Это последствие действовало
  до ADR 0006; теперь начало и конец хранятся в самой позиции `commitment`, а не
  в отдельной очереди агентов.
- `morning_brief` становится производным от Router (формат вывода), а не
  отдельной механикой. Решение по нему — отдельно.

## Открыто

Решение по Corrections Log, `morning_brief` и `session_start_context` не принято.

владелец отметил, что к архитектуре операционного слоя нужно подойти системно, а не
механика за механикой. Эта ADR фиксирует одно решение и не предвосхищает общий
пересмотр — см. TASK-005.
