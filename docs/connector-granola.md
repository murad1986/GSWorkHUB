# Коннектор Granola

Забирает встречи из Granola и кладёт их в зону приёма `raw/inbox/`: сводку и
полную расшифровку. Разбор — отдельная работа человека и агента, коннектор его
не делает.

## Команда

```
make granola                    # за последнюю неделю
make granola SINCE=2026-01-01   # с указанной даты
python3 tools/granola.py --dry-run --since 2026-01-01   # показать, ничего не писать
```

## Ключ

Ключ Granola (`grn_…`) лежит в связке ключей macOS, в складе его нет:

```
security add-generic-password -U -s granola-api -a workhub -w <ключ>
```

Переменная `GRANOLA_API_KEY` перебивает связку — удобно для разовой проверки.
Ключ выдаётся на тарифе Business/Enterprise: Granola → Settings → API.

## Что он пишет

Файл в `raw/inbox/` с шапкой `type: meeting`, датой встречи по местному времени,
`source: granola` и `source_ref` — идентификатором заметки вида `not_…`. В теле —
сводка Granola и расшифровка, где подряд идущие реплики одного голоса склеены в
абзац: Granola режет речь на куски по паузам, и без склейки файл нечитаем.

Контейнер, участников и режим разговора коннектор **не проставляет**. Это
суждение, а не факт из записи, и требовать их на входе значит требовать
результат разбора до разбора (storage-schema, «Приём: чего нельзя требовать на
входе»).

## Три исхода прихода

**Новое** — записать. **Правка записанного** — запрещена: коннектор никогда не
открывает существующий файл. **Повтор** — отбросить: разговор узнаётся по паре
`source` + `source_ref`, и если она уже есть в `raw/`, приход отбрасывается
молча.

Ранние записи ссылались на Granola названием встречи (`source_ref: "Granola:
Process mapping — Альфа"`), а не идентификатором. Коннектор узнаёт и такой вид, и
не заводит вторую копию уже записанного разговора.

## Запись перечитывается после записи

В первом живом прогоне 30 июля две записи из семнадцати не оказались на диске, а
коннектор отчитался обо всех семнадцати. Причина не установлена; повторный
прогон дозабрал недостающее и не задублировал остальные пятнадцать. С тех пор
каждый записанный файл читается обратно и сверяется с тем, что писали:
расхождение останавливает прогон. Отчёт об успехе без данных — тот самый класс
отказа, ради которого написан `verify` (known-failure-modes, пункт 14).

## Пределы Granola

Пять запросов в секунду, не больше тридцати заметок на страницу. Коннектор
держит паузу в четверть секунды между запросами. API отдаёт только те встречи,
для которых Granola успел сделать сводку.
