# Промпт: поставить склад с нуля одной вставкой

Копируется целиком и вставляется в Codex (или другого агента с доступом к
терминалу и вашим MCP-серверам). Ничего заранее делать не нужно: агент сам
создаст папку, заберёт систему, проверит её, спросит недостающее и соберёт в
склад рабочий контекст.

---

Ты ставишь мне рабочую операционную систему GSWorkHUB и наполняешь её моим
рабочим контекстом. Делай всё сам, спрашивай только то, чего не можешь узнать
из машины. После каждого шага коротко отчитывайся и продолжай; останавливайся и
жди ответа только там, где это сказано явно.

**Границы на всю работу.** Наружу не пишешь ничего: ни сообщений, ни
комментариев, ни правок в чужих документах — только чтение. Не выдумываешь
участников, даты, сроки и цитаты: источник не дал — поле пустое. Решения,
деньги, сроки и обязательства перед людьми показываешь мне на подтверждение, а
не записываешь молча.

## 1. Поставить систему

```bash
mkdir -p ~/gsworkhub && cd ~/gsworkhub
git clone https://github.com/murad1986/GSWorkHUB.git .
rm -rf .git && git init -b master && git add -A
git commit -m "склад заведён"
```

История публичного репозитория отвязана намеренно: дальше склад наполняется
рабочими данными и живёт только у меня. Если у меня есть закрытый репозиторий
для него — спроси адрес и добавь как `origin`; нет — оставь локальным.

Зависимости:

```bash
python3 -m pip install -r requirements.txt || {
  python3 -m venv .venv && .venv/bin/python -m pip install -r requirements.txt
  echo 'PY='"$PWD"'/.venv/bin/python'
}
```

Если пришлось поднимать `.venv`, дальше все команды `make` запускай с
`PY=$PWD/.venv/bin/python` и скажи мне об этом — эта же переменная понадобится
в расписании.

Проверка:

```bash
make gates
```

Обе строки обязаны быть зелёными: `VERIFY: сошлись все N случаев` и
`ЛИНТ: чисто`. Красное — остановись и покажи вывод как есть.

## 4. Подключить источники

Сначала посмотри, что уже есть:

```bash
make check-env
codex mcp list
```

Затем по одному, с проверкой каждого:

- **Telegram** — разговорный вход и голос. Нужны токен бота от `@BotFather` и мой
  числовой id; кладутся в `config/secrets.env` (образец рядом — `.example`).
  Проверка: `make telegram ACTION=check`.
- **Deepgram** — расшифровка голосовых, ключ `DEEPGRAM_API_KEY`.
- **Google Calendar** — контекст дня. Проверка: `make calendar`.
- **Всё остальное — через твои MCP-серверы**: диктофон Plaud, переписка,
  документы, базы, трекеры, доски. Для каждого возьми одну свежую запись и
  покажи мне, что именно видишь. Дальше они работают через общий вход
  `tools/capture.py` — описание в `docs/connector-plaud.md`.

Ключей у меня может не быть под рукой — спроси. Ни один источник не обязателен:
без него склад работает целиком, молчит только этот вход. Обходных путей не
придумывай, скажи прямо, чего не хватает.

**Покажи таблицу:** источник — подключён или нет — чем проверено.

## 5. Спросить рамку и собрать контекст

Спроси по одному: какие клиенты и проекты идут сейчас; какие чаты считать
рабочими; где лежат документы; за какой период поднимать историю; чего не тянуть
вовсе. Ответы сохрани событием в `raw/sources/<дата>-ramka-sbora.md`.

Потом собирай — от свежего к старому, партиями по 20–50 записей:

```bash
python3 tools/capture.py --file partiya.json
```

Формат партии — список объектов, обязательны `source`, `external_id`, `date`,
`title`:

```json
[{"source": "plaud", "external_id": "rec_8123", "date": "2026-08-14",
  "title": "Планёрка по маршрутам", "body": "<дословное содержимое>",
  "fields": {"container": "work/clients/<кто>"}}]
```

Правила: `source` пишется одинаково всегда (иначе одна запись ляжет дважды);
`external_id` берётся из источника, а не выдумывается; `body` — дословно, без
пересказа и сокращений; `container` ставится только когда клиент назван в самой
записи. Повторы система отбрасывает сама, поэтому лучше захватить лишнее, чем
потерять. После каждой партии — `make lint`.

**Покажи по каждому источнику:** сколько пришло, сколько принято, сколько
отброшено повторами, что не удалось и почему.

## 6. Разобрать первую волну

Разбирай по одному источнику, четырьмя проходами: факты → противоречия →
причины → следствия. Заводи контейнеры под то, что реально идёт: клиентов,
программы, людей. Из разобранного предлагай обязательства, вопросы, риски,
процессы и решения — каждое со ссылкой `origin` на событие в `raw/`.

**Каждую позицию показывай мне целиком до записи**: формулировка,
ответственный, срок, следующий шаг, источник. Я подтверждаю — ты записываешь.
Не больше трёх находок за раз.

## 7. Поставить автосбор три раза в сутки

```bash
make context DRY=1
make context
```

Затем поставь расписание на 9:00, 14:00 и 21:00 по инструкции
`docs/avtosbor-konteksta.md` — на macOS это launchd-файл
`~/Library/LaunchAgents/com.gsworkhub.context.plist`, пути и имя пользователя
подставь настоящие. Проверь, что первый заход отработал:
`~/Library/Logs/GSWorkHUB/context.log`.

## 8. Отчитаться и закоммитить

```bash
make gates && make welcome && make today
```

Скажи мне: какие источники подключены и какие нет; сколько событий в складе и за
какой период; какие контейнеры заведены и сколько в них открытых позиций; что
покажет утренний вход завтра; три вещи, которые сделать не смог, и что для них
нужно. Закоммить всё одним понятным коммитом.
