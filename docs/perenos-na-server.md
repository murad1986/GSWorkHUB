# Перенос склада на сервер

Готовится под решение 8 августа 2026: постоянный слушатель живёт на Amvera,
синхронизируется весь склад ([архитектура](architecture-v3.md), раздел
«Где живёт постоянный слушатель»).

## Что проверено на этой машине

- **Чистый клон работает.** `git clone` в пустой каталог, `python3 tools/verify.py`
  — 307 случаев сошлись, линт отработал на 1250 файлах. Ни одна проверка не
  зависит от машины, на которой писалась.
- **Размер клона — 41 МБ**, из них история 15 МБ. До упаковки репозиторий весил
  89 МБ россыпью: 14 714 объектов и 77 временных огрызков в `.git/objects`.
  Упакован `git gc --prune=now` 9 августа.
- **Зависимость одна** — PyYAML, вынесена в `requirements.txt`.

## Чего на сервере не будет

Три вещи работают только на этом ноутбуке, и слушатель должен либо получить их
иначе, либо честно молчать о них:

| Что | Почему не переносится | Как быть |
|---|---|---|
| Ключ Granola | берётся из Keychain macOS | переменная `GRANOLA_API_KEY` |
| Доступ к календарю | `gws` хранит зашифрованные креды в `~/.config/gws` | перенести `client_secret.json` и `credentials.enc` секретами либо авторизовать заново |
| Доступ к TickTick | OAuth-токен в `~/.config/ticktick-mcp/config.json`, действует до 13 октября 2026 | создать постоянный API token в настройках TickTick и задать `TICKTICK_API_TOKEN`; запасной вариант — полный набор OAuth refresh-данных |
| Данные о восстановлении | `capacity` читает выгрузки Apple Health из iCloud | на сервере ёмкость будет «неизвестна», и это правильный ответ, а не ноль |

## Где секреты живут на этой машине

`config/secrets.env` — файл в проекте, но вне git (закрыт в `.gitignore`, права
`600`). Инструменты читают его сами; **окружение старше файла**, поэтому на
сервере те же имена задаются переменными в панели, а файл туда не копируется.

Причина такого устройства простая: склад уезжает на сервер целиком, и всё, что
попало в историю репозитория, уедет вместе с ним и останется там навсегда —
включая отозванные потом ключи.

Сейчас в файле: `TELEGRAM_BOT_TOKEN` — бот `@ivan4b_bot` («Worker», id
8751283660), проверен живым запросом 9 августа 2026.

## Секреты, которые нужно завести в панели Amvera

Ни один из них не хранится в репозитории и не должен туда попасть.

- `GRANOLA_API_KEY` — ключ Granola;
- `TELEGRAM_BOT_TOKEN` — токен бота;
- `TELEGRAM_ALLOWED_USER_ID` — единственный Telegram-пользователь, чьи сообщения
  бот имеет право принимать;
- `DEEPGRAM_API_KEY` — расшифровка голосовых сообщений Nova-3;
- содержимое `~/.config/gws/client_secret.json` и `credentials.enc`;
- `TICKTICK_API_TOKEN` — предпочтительный постоянный ключ из Settings → Account
  → API Token;
- либо набор OAuth: `TICKTICK_ACCESS_TOKEN`, `TICKTICK_EXPIRES_AT`,
  `TICKTICK_REFRESH_TOKEN`, `TICKTICK_CLIENT_ID`, `TICKTICK_CLIENT_SECRET` —
  тогда дежурный сам обновляет access token;
- Google: `gws` и его OAuth-доступ с правом `calendar.events`; на сервере можно
  передать результат `gws auth export --unmasked`, закодированный в base64, как
  `GOOGLE_WORKSPACE_CREDENTIALS_B64`. При старте он попадёт в закрытый файл
  постоянного тома, а refresh token будет обновлять доступ без участия человека.

## Порядок переноса

1. Завести приватный git-remote для склада и запушить `master`.
2. Развернуть приложение на Amvera из этого репозитория.
3. Завести секреты из списка выше.
4. Проверить на сервере: `python3 tools/verify.py` и `python3 tools/lint.py`
   должны дать те же числа, что на ноутбуке. Расхождение означает, что уехало
   не всё.
5. Проверить внешние доступы поимённо: `make granola`, `make ticktick`,
   чтение календаря. Каждый, который не отвечает, должен называть причину, а не
   притворяться пустым.
6. Проверить разговорный вход: `make telegram ACTION=check`.
7. Проверить полный обмен: `make sources`. Подходящее обязательство без поля
   `ticktick` должно появиться в приложении и получить связь в карточке;
   задача с явным временем должна получить отдельный блок календаря; повторный
   запуск не создаёт копий. Тестовый блок удалить после проверки: обязательство
   должно остаться открытым, а время — сняться.
8. Запустить дежурного: `python3 tools/duty.py`. Он держит одновременно Telegram
   и сверку источников; остановка любого процесса останавливает весь контейнер,
   чтобы платформа перезапустила его, а половина системы не молчала.

## Что делает разговорный вход

Текст и голос проходят один `dialogue.py`. Ответ через reply получает связь из
журнала и не угадывает предмет разговора; через два часа связь считается
устаревшей и бот задаёт один уточняющий вопрос.

Голос сначала сохраняется побайтно в `raw/inbox/`, затем уходит в Deepgram
Nova-3 с `language=ru`, пунктуацией, умным форматированием чисел и словарём до
100 имён, компаний и терминов склада. Расшифровка кладётся рядом отдельным
Markdown-событием. Интерпретация в сырьё не пишется.

## Правила, которые нельзя нарушить при переносе

**Правда живёт в git.** Сервер — второй рабочий клон одного репозитория, а не
вторая база: `pull`, работа, `push`. Расхождения git показывает, а не прячет.

**Слушатель пишет только через команды и гейты** — `make work`, `make attention`,
линтер. Прямых правок файлов мимо проверок быть не должно: иначе появится
состояние, которого проверки не видят.

**Отсутствие доступа называется вслух.** Пустой календарь и нечитаемый календарь
для человека выглядят одинаково, а значат противоположное.
