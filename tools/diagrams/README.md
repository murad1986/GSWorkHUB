# Схемы процессов

Инструмент собирает схемы из описаний и рисует их картинкой. Описание — это
файл в `schemes/`, схема — файл `.excalidraw`, который открывается и правится
на excalidraw.com. Всё считается на своей машине, наружу ничего не уходит.

## Собрать

```bash
./build_all.sh                        # все схемы
./build_all.sh schemes/alfa/sipoc.yaml # одну
```

На выходе в `out/`: `.excalidraw` для правки руками, `.png` и `.svg` для показа.

Если библиотеки ещё не поставлены — сначала `npm install` (около 300 МБ, минута).

## Что собрано

По решению `ALF-D-004`, процесс `ALF-P-001` — пять видов:

| Файл описания | Схема | На какой вопрос отвечает |
|---|---|---|
| `schemes/alfa/storm.yaml` | стена событий | что происходит и где спорят |
| `schemes/alfa/sipoc.yaml` | SIPOC | границы и обмен |
| `schemes/alfa/lanes.yaml` | дорожки | кто за что отвечает |
| `schemes/alfa/traces.yaml` | карта следов | что где записывается |
| `schemes/alfa/money.yaml` | путь денег | где лежат деньги и чей риск |
| `schemes/alfa/chains.yaml` | две цепочки | чем длинная ветка отличается от короткой |

## Новая схема

Новая диаграмма — это новый файл в `schemes/`, код при этом не меняется. Виды
блоков, формат описания и ловушки — в скилле `excalidraw`.

Одно правило, о которое спотыкаются все: **текст с запятой или двоеточием
берётся в одинарные кавычки**, иначе YAML разберёт его не как строку.

## Что не хранится в git

Библиотеки (`node_modules`), картинки (`out/*.png`, `out/*.svg`) и служебные
сборки. Картинки пересобираются из описаний, поэтому в истории им не место.
Сами `.excalidraw` хранятся: сборка детерминированная, и правки в них видно
построчно.
